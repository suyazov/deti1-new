# Правила исполнителя — deti1.ru

## Вход и способ работы

Прочитать свежий main, [PROJECT_CONTEXT](docs/PROJECT_CONTEXT.md), связанную Issue/PR и документы по задаче. Проверить отсутствие конкурирующего автора. Старые чаты, временные серверные пути и журнал сессий не заменяют текущую версию.

Для DETI-00 действует D-09: «делай без bridge». Продолжать эту же задачу напрямую через GitHub; не запускать Bridge/Kimi, не требовать onboarding и не менять видимость репозитория. Общие границы полномочий и exact-head приёмки — в [регламенте](https://github.com/suyazov/bridge-sy9/blob/main/docs/UNIVERSAL_ORCHESTRATION_REGULATION.md). Read-only статус прежней заявки используется только для проверки пересечения. Указание не переносится автоматически на другие проекты.

## Обязательные ограничения

- Калькулятор: соблюдать D-01 в [DECISIONS](docs/DECISIONS.md). Не удалять, не закрывать заявкой и не менять математику под видом дизайна.
- Зверюшки: соблюдать D-02 и [VISUAL_DIRECTION](docs/VISUAL_DIRECTION.md). Текущие персонажи не приняты; конкретный новый вариант выбирает Анна.
- Сохранять B2B-назначение и существующий стек. Это не разработка CRM/SaaS.
- Не выдумывать цифры, отзывы, награды, гарантии, состав команды или готовность программного обеспечения. Цены и статусы — только в [CONTENT_MODEL](docs/CONTENT_MODEL.md).
- Не публиковать частные финансовые документы, персональные предложения, данные клиентов и секреты. Закрытые материалы — ссылками, без копирования сырого содержимого.

## Документация и проверка

Один факт — один владеющий документ: контекст/текущее действие, решения, содержание, визуальное направление, план, источники. В остальных местах ссылки. Изменённое решение обновлять в том же PR. Не превращать AGENTS в дневник. Исторический AGENTS доступен по immutable-ссылке в SOURCES; `deti1_session_summary.md` и `seo-geo-audit-report.md` сохраняются.

В DETI-00 разрешены только README, AGENTS и шесть перечисленных документов `docs/`. Все остальные файлы, включая `src/`, `public/`, `index.html` и зависимости, должны быть побайтно сохранены. Проверить diff, ссылки, решения, происхождение цен; независимый read-only разбор точного head предшествует обычному merge. Новый head/base требует повторной проверки. Без force и административного обхода.

Для дальнейших UI-задач нужны desktop/mobile, доступность, сценарии и регрессия калькулятора. Исторический Lighthouse не является свежим тестом. Issue, PR, merge и HTTP 200 не доказывают завершённость сайта.

Production, DNS, секреты, платежи, удаление, архивирование репозиториев, изменение видимости и общих ресурсов требуют отдельного точного разрешения. При будущем разрешённом выпуске сохранять `api/`, `v1/`, `consent.html`, `privacy-policy.html` и внешнюю конфигурацию формы, пока отдельный scope не разрешает их изменение. Сначала проверить фактическое состояние; старые команды очистки не разрешают удаление.
